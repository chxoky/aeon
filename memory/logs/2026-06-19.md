## [20:28 PT] Cowork — Token debloat + dev-agent framework integration

Long session. Started as "integrate a 10-file AI-identity framework into the project,"
pivoted to the real underlying concern (per-session token cost), did the cleanup, then
came back and deployed the framework in trimmed form. Full record below.

### Context / motivation
- Kyle dumps this project's context into many fresh Cowork + Claude Code sessions, and a
  prior session estimated ~25–30k tokens consumed by system prompt/context per session.
- He brought in a 10-file coding-agent framework (the "acidgreenservers" gist: AGENT,
  AGENTS, BRAIN, GEPHYRO, HEART, MEMORY, RULES, STATE, TOOLS, USER) and asked how to
  integrate it efficiently for this project + all future projects.
- Key realization that shaped everything: the framework is for the **developer agent**
  (interactive Claude Code/Cowork editing the repo), which is a DIFFERENT agent from
  **Aeon the runtime** (autonomous, runs in GitHub Actions). They must not bleed into
  each other — Claude Code auto-reads AGENTS.md/CLAUDE.md, so committing framework files
  to the repo would pollute Aeon's runtime persona AND pay their token cost on every cron.

### Diagnosis: where the ~25–30k actually goes
- Honest correction surfaced to Kyle: the framework is NOT a debloater — naively it would
  ADD tokens. The big cost is mostly things CLAUDE.md can't touch:
  - Cowork app system prompt (fixed by Anthropic).
  - **Installed plugin/skill catalogs** (the big movable lever) — each injects its full
    skill list every session.
  - Connected MCP/connector tool schemas.
- Real levers = uninstall unused plugins + disconnect unused connectors.

### Changes made

1. **Plugin/connector prune (Kyle executed in Settings; I produced the kill-list)**
   - Removed plugins: twilio-developer-kit (biggest, 60+ skills), carta-investors,
     sp-global, finance, data, product-management, airtable, cowork-plugin-management,
     and servicenow-sdk/fluent.
   - Disconnected connector: Spotify.
   - Kept (evidence of use): engineering (github/code-review/debug for the repo),
     desktop-commander, productivity, pdf-viewer; connectors Cloudflare (.wrangler/Worker
     cron), FMP (financial market data — on-theme for stocks+crypto), Gmail.
   - Why: these dense catalogs were the bulk of per-session overhead and none are used by
     a Telegram/Discord trading bot. This was the single largest token win.

2. **Trimmed `Telegram Bot Discord/X/CLAUDE.md`** (the Cowork project-instructions file,
   loads every session): 103 lines / 6.4KB → 70 lines / 4.1KB (~⅓ off, lossless).
   - Extracted §5 "Maximize AEON's framework" (generators, rate-limit scheduling, chains,
     audits, credential separation, MCP surfacing) verbatim into new file
     `X/aeon-levers.md`, replaced with a one-line pointer. Why: it's reference material
     only relevant when planning/extending skills, but was loading on every session
     (setup, troubleshooting, etc.) — contradicted the file's own §1 cost discipline.
   - Merged §2 (one-task-per-session) and §4 (restart discipline) which overlapped, and
     renumbered §5→§4. Why: redundancy removal, no information lost.
   - Caveat flagged to Kyle: mirror this in Cowork Settings if instructions are also
     pasted there.

3. **Left `aeon/CLAUDE.md` untouched.** Assessed all 137 lines; every section is
   load-bearing for the runtime (memory routine, sandbox prefetch/postprocess, notify
   fan-out, chaining, security). No genuinely lossless trim available, and Kyle gated the
   edit on "only if lossless." ~2k tokens/run, far smaller than the plugin problem anyway.

4. **Deployed the framework — trimmed, local, Actions-insulated.** Three per-project
   dynamic files written to the aeon repo root and **gitignored** (local interactive
   sessions only; never committed; never read by Actions):
   - `USER.md` — operator + project profile (Kyle, trading bot vision; some fields left
     for him to refine). Distinct from soul/ (the bot's output voice).
   - `STATE.md` — trimmed durable state: topology phase = `bridge`, the 4-invariable map
     tailored to AEON (state in memory/, feedback via notify/dashboard/audits, credential
     separation as load-bearing, cron/Worker timing), git hygiene rules.
   - `BRAIN.md` — wisdom-seed schema (compression/generative/falsifiable/decompressible)
     + 3 starter seeds about context budget and keeping the framework off the runtime.
   - `.gitignore` — appended USER.md / STATE.md / BRAIN.md under a new dev-framework
     section.
   - Dropped from the framework entirely: GEPHYRO.md, HEART.md, framework's own MEMORY.md
     (Aeon's memory/ is better), and the mystical halves of AGENT/AGENTS/BRAIN. Why: the
     dense identity-poetry consumes tokens without changing agent behavior; kept only the
     operational mechanics, consistent with §1 cost rules.

5. **Global operating block → `~/.claude/CLAUDE.md`.** Distilled AGENT+AGENTS+TOOLS+RULES
   + BRAIN schema into one lean block (4 invariables, ambiguity tiers, verification gate,
   red lines, package-freshness security gate, core-five tools, commit-consent,
   self-review). Couldn't write it via tools (~/.claude is platform-protected — can't be
   mounted), so produced a clean file in outputs and Kyle installed it via
   `cp ... ~/.claude/CLAUDE.md`; verified header present. Loads into every interactive
   Claude Code session on his machine; NOT read by Actions (runs on GitHub runners), so
   zero runtime cost. This is the always-on layer that tells each session to read
   STATE/BRAIN/USER from whatever repo is open.

### Net architecture
- Framework governs **you editing Aeon** (local CCC only, trimmed, gitignored/global).
- Aeon's runtime (CLAUDE.md + memory/) and the Actions token budget are **untouched**.
- They never collide because they load in different execution contexts.
