# twitterapi.io webhook stopped delivering

## Symptom

Zero `x-trader-monitor` runs on origin/main since 2026-06-16 (~27 days), while
`discord-trader-monitor` fires many times daily over the same period. 12 active
traders posting nothing for a month is not plausible — the X inbound path is dead.

## What was ruled out (2026-07-13 session)

- **Worker → GitHub → skill path works.** Synthetic POST to
  `https://trading-bot.chxoky.workers.dev/twitter` with a twitterapi.io-shaped
  payload dispatched `x-trader-monitor` within seconds; the skill classified the
  test tweet correctly (HR-1 silent skip) and auto-committed its log.
- **Username field mapping is not the cause this time.** The 2026-06-16 fix
  (`tweet.user.screen_name` fallback chain in `handleTwitter`) covers all known
  payload shapes; the previous same-symptom incident (ISS-less, fixed 06-16) was
  this mapping, but events then were at least REACHING the Worker.

## Remaining suspects (in likelihood order)

1. **twitterapi.io credits/balance exhausted** — webhook tweet delivery is paid
   per event; delivery stops silently at zero balance.
2. **Webhook rule expired or deactivated** on the twitterapi.io side.
3. Webhook endpoint URL deregistered.

## How to diagnose

Query the twitterapi.io API with `TWITTERAPI_IO_KEY` (GitHub secret — not
available locally): check account balance and `GET` the tweet-filter/webhook
rules. After the v0.1 secretcurl migration (PR #5) any skill can do this with
`./secretcurl -H 'x-api-key: {TWITTERAPI_IO_KEY}' ...` by declaring the key in
`requires:`. The `trader-x-bootstrap force` run from the PR branch also
exercises the key — if that run fetched tweets successfully, the key and
balance are fine and the webhook RULE is the problem; if it got auth/quota
errors, it's the balance/key.
