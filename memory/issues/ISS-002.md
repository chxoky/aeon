# twitterapi.io webhook stopped delivering

## Symptom

Zero `x-trader-monitor` runs on origin/main since 2026-06-16 (~27 days), while
`discord-trader-monitor` fires many times daily over the same period. 12 active
traders posting nothing for a month is not plausible — the X inbound path is dead.

## What was ruled out (2026-07-13 session)

- **Worker → GitHub → skill path works.** Synthetic POST to
  `https://trading-bot.chxoky.workers.dev/twitter` with a twitterapi.io-shaped
  payload dispatched `x-trader-monitor` within seconds; the skill classified the
  test tweet correctly (HR-1 silent skip) and auto-committed its log.
- **Username field mapping is not the cause this time.** The 2026-06-16 fix
  (`tweet.user.screen_name` fallback chain in `handleTwitter`) covers all known
  payload shapes; the previous same-symptom incident (ISS-less, fixed 06-16) was
  this mapping, but events then were at least REACHING the Worker.

## Root cause narrowed (2026-07-13, same session)

`trader-x-bootstrap force` run from the PR #5 branch (run 29299646760) fetched
**97 tweets from 10/12 watched accounts (2026-07-11 → 07-13)** via the new
secretcurl path using `TWITTERAPI_IO_KEY`. Therefore:

- API key valid, account balance fine, REST access working.
- Traders are actively posting (97 tweets in 3 days) while the webhook
  delivered ZERO events over the same window.

→ **The twitterapi.io webhook/tweet-filter RULE itself is dead** (expired,
deactivated, or deregistered). Not credits, not the Worker, not the field
mapping.

## Fix

Log into the twitterapi.io dashboard (or use the rules API with
`TWITTERAPI_IO_KEY` via `./secretcurl` post-merge): re-create/re-activate the
tweet-filter webhook rule for the 12 watched accounts pointing at
`https://trading-bot.chxoky.workers.dev/twitter`, then confirm one real tweet
event produces an x-trader-monitor run. Also worth checking whether rules
auto-expire — if so, add a rule-health check to `api-health-probe` or
`heartbeat` so a dead rule alerts within a day instead of a month.
